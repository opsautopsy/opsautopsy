# Contributing to OpsAutopsy

Thank you for your interest in contributing to **OpsAutopsy**.

OpsAutopsy is designed as a **post-incident Kubernetes forensics engine**.
We value contributions that improve clarity, correctness, and production
realism.

---

## How to Contribute

### 1. Fork the Repository
Create a fork and work from your own branch.

### 2. Make Focused Changes
- Keep changes small and well-scoped
- Avoid unrelated refactoring
- Follow existing project structure and style

### 3. Commit Guidelines
- Use clear, descriptive commit messages
- One logical change per commit

### 4. Open a Pull Request
Include:
- What problem the change solves
- Why the change is needed
- Any design considerations

---

## What We Accept

✔ Bug fixes  
✔ Documentation improvements  
✔ Performance improvements  
✔ Incident detection logic improvements  
✔ Storage / correlation enhancements  

---

## What We Avoid

✖ Large refactors without discussion  
✖ Feature creep (monitoring, alerting, dashboards)  
✖ Cloud-provider lock-in  
✖ Changes that mutate cluster state
